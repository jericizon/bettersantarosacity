# Better Santa Rosa City

Independent, community-maintained public information portal for Santa Rosa City, Laguna. Not an official City Government website; every dataset links back to primary sources (COA, PSA, DBM, city ordinances, the official city directory) so residents can verify the records themselves.

**Stack:** Nuxt 4 · Vue 3 (`<script setup lang="ts">`, strict TS) · Tailwind CSS · Zod-validated JSON data · MapLibre GL · Pagefind search · Vitest

## Commands

```bash
pnpm install          # also runs nuxt prepare
pnpm dev              # dev server on :4027
pnpm test:run         # vitest unit suite
pnpm typecheck        # vue-tsc via nuxt
pnpm build:prod       # sync data -> sitemap -> nuxt generate -> pagefind -> dist/
pnpm serve            # serve dist/ on :4026
```

## Project structure

```text
pages/          routes: index, explore, barangays, government, money,
                projects, laws, services, data, sources, search, about/media
components/
  civic/        header/footer, hero, weather system, map explorer, ticker
  data/         source badges, freshness stamps, stat cards
  editorial/    section headers
  government|money|projects|search|media/   per-domain cards & widgets
data/           curated JSON registries (the site's content layer)
types/civic.ts  zod schemas every data file is validated against in tests
scripts/        sync-public-data, generate-sitemap, generate-barangay-areas
tests/unit/     vitest specs: schema validation + component behavior
docs/superpowers/   specs, plans, QA reports
```

## Data conventions

- Content lives in `data/*.json` (budgets, projects, laws, services, officials, departments, hotlines, barangays, media, sources, city profile).
- Every registry is validated against a zod schema in `types/civic.ts` by a spec in `tests/unit/`. Add a field to JSON, add it to the schema.
- Every record carries `source` (publisher + URL) and `lastVerified` (ISO date); the UI renders both.
- `scripts/sync-public-data.mjs` copies registries into `public/data/` at build time; `generate-sitemap.mjs` builds `sitemap.xml`.

## Notable features

- **Weather-reactive hero** (`composables/useWeather.ts` + `WeatherAmbience/WeatherChip/CloudCharacter/WeatherDraggable/WeatherFogVeil`): live Open-Meteo conditions for Santa Rosa drive an ambient animation layer (sun, clouds, rain, storm, snow, fog) across the banner. Clouds and birds are draggable/throwable and glide home. All effects respect `prefers-reduced-motion`. A dev-only scene switcher (`WeatherSceneSwitcher.vue`, gated on `import.meta.dev`) pins to the hero's right edge for manual scene testing.
- **Emergency hotline ticker** (`HotlineTicker.vue` + `data/hotlines.json`): scrolling tap-to-call strip on the hero's top edge; numbers verified against the official city directory.
- **Search:** Pagefind static index over `dist/` (`pnpm index:search`, runs in `build:prod`).
- **Map:** MapLibre explorer over the 18-barangay coverage layer (`data/barangay-areas.json`, generated by `scripts/generate-barangay-areas.mjs` from OSM centroids; simplified, not cadastral).

## Testing & QA

```bash
pnpm test:run    # schema integrity + component behavior (happy-dom)
pnpm typecheck
```

Specs pair data-integrity checks (every JSON record parses, media files exist on disk) with component tests (VTU + happy-dom). Browser QA uses Playwright scripts under `~/.cache/client-demo-presentation/` against a running dev server.

## Deployment

Static site (`nitro.preset: cloudflare-pages-static`). `pnpm build:prod` emits a fully prerendered `dist/` with the Pagefind index; deploy `dist/` to Cloudflare Pages. No server runtime, no database.
